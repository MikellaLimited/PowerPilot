PowerPilot 0.6.16 — стабильное обновление температурных датчиков без перезаписи занятых DLL

Исправления температурного модуля:
1. Исправлена регрессия 0.6.15, из-за которой при ожидающем обновлении провайдера старый PowerPilotSensors.exe переставал перезапускаться. Из-за этого sensors.json становился устаревшим и в интерфейсе оставалась только температура Storage.
2. Обновление LibreHardwareMonitor теперь выполняется side-by-side: новый набор DLL разворачивается в отдельную версионную папку, компилируется и проверяется до остановки текущего коллектора. Загруженные System.Memory.dll и другие CLR-зависимости больше не перезаписываются на месте.
3. После подготовки нового runtime задача PowerPilot Hardware Sensors переключается на новый PowerPilotSensors.exe одним шагом. Старый runtime остаётся нетронутым и не блокирует обновление.
4. Добавлен active_provider_dir.txt. PowerPilot всегда знает, какой versioned runtime сейчас активен, и последующие восстановление задачи/запуск fallback используют именно его.
5. Новый collector revision 7 поддерживает --output-dir: versioned runtime пишет sensors.json и collector_status.json в общий HardwareProvider, поэтому UI не зависит от физической папки DLL.
6. Восстановление Task Scheduler и fallback-collector также передают общий output-dir; после будущего self-repair снимок датчиков больше не уезжает в runtime-подпапку.
7. Ручное обновление теперь возвращает точную ошибку из повышенного helper через отдельный result-файл вместо бесполезного «exit status 1».
8. После успешного переключения PowerPilot ждёт свежие sensors.json + collector_status.json и только затем считает обновление завершённым.

Поведение обновления:
- автоматическая проверка наличия обновления сохраняется;
- автоматическая установка/повышение прав не выполняются;
- для перехода со старого v0.9.6 нужно один раз нажать «Обновить датчики температур» в Настройки → Данные и подтвердить UAC;
- PawnIO повторно устанавливать не требуется при обычном обновлении существующей установки.
