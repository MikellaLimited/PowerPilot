PowerPilot 0.6.15 — исправление повторных PowerShell-окон при работе температурных датчиков

1. Исправлен бесконечный цикл автоматического повышенного обновления температурного провайдера.
   В 0.6.14 после неудачной транзакции обновления PowerPilot повторял её на каждом 5-секундном цикле температур,
   из-за чего постоянно запускались PowerShell/UAC и в журнале появлялись повторяющиеся exit status 1.

2. Автоматическая проверка обновлений датчиков сохранена, но автоматическая установка/замена провайдера больше не выполняется.
   Если пакет LibreHardwareMonitor устарел, PowerPilot продолжает использовать установленный коллектор и предлагает
   вручную нажать «Обновить датчики температур» в Настройки → Данные.

3. Все PowerShell-процессы, используемые PowerPilot в фоне, дополнительно запускаются с -WindowStyle Hidden
   вместе с CREATE_NO_WINDOW/HideWindow. Повышенные PowerShell-помощники также создаются скрытыми;
   системное окно UAC при явно запрошенной пользователем установке/обновлении остаётся ожидаемым.

4. Убрано периодическое прямое загрузочное подключение LibreHardwareMonitorLib.dll из краткоживущего PowerShell-процесса.
   Низкоуровневый LibreHardwareMonitor теперь читает только постоянный elevated collector PowerPilotSensors.exe.
   Фоновый Windows fallback оставлен только для WMI, ACPI и Storage Reliability.
   Это устраняет один из источников блокировки System.Memory.dll при обновлении провайдера.

5. При ручной установке/обновлении датчиков температур периодический температурный sampler временно останавливается,
   чтобы фоновые probes не конкурировали с заменой runtime-файлов. После завершения sampler запускается снова.

6. Версия приложения и установщика обновлена до 0.6.15.

Примечание: реальный UAC / Task Scheduler / PawnIO / hardware-sensor runtime требует проверки на Windows.
